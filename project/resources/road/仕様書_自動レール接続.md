# 仕様書: 自動レール接続 (スナップ) とジョイント表示

Claude Code に渡して実装する想定の仕様書。
参考イメージ: プラレール/BRIOのように近づけるだけでカチッと繋がり、接続部に
凸ジョイントが見える。検証画像: joint_demo.png (2本溶接 + 3方向ジャンクション)

## 0. 前提 (現状)

- レールエディタに手動の「端点を溶接」「近い線を連結 (約1.2m)」ボタンが既にある
  → 本仕様はこれの **自動化 + 可視化 + 管理UI**。接続処理そのものは既存を呼ぶ
- ジャンクションの見た目は GUIDE_ジャンクション生成.md のパッチ生成を使用
- 新モデル road_joint.glb を同梱済み (136三角形 / 0.4×0.82m / 高さ4cm /
  アトラス共有なので追加テクスチャなし)

## 1. 自動スナップ (エディタ機能)

### 1-1. 検出
レール端点のドラッグ中、毎フレーム以下を判定:
- (a) 他レールの端点との距離 ≤ snapDistance → **端点溶接** 候補
- (b) 他レールの曲線上の最近点との距離 ≤ snapDistance → **途中連結(T字)** 候補
- (a)(b) 両方あるときは距離が近い方を優先
- 最近点計算は FrameCache のテーブル(0.25m刻み)を総当たり→前後だけ精密化で十分

### 1-2. プレビューと確定
- 候補がある間: 接続先を緑ハイライト + スナップ後の位置に端点ゴースト +
  ジョイントの半透明ゴースト表示
- ドロップ (マウスアップ) で確定: 既存の溶接/連結処理を呼び、端点座標を
  スナップ位置へ吸着させる
- Escドロップ or 候補外でドロップ → 接続しない (通常配置)

### 1-3. 設定 (調整項目 Global パネルに追加)
| 項目 | 既定値 | 範囲 |
|---|---|---|
| autoSnap | ON | ON/OFF |
| snapDistance | 1.2 m | 0.3〜3.0 |
| jointVisible | both | editor / both / off |

## 2. ジョイント表示 (自動配置・保存しない派生データ)

- 接続ノードから毎回導出する (シーン保存にジョイント情報は含めない)
- 配置ルール:
  - 2本の端点溶接: ノード中央に1個。向き = 2方向の二等分線 (凸をどちらかへ)
  - ジャンクション(3本以上): 各入口の t_cut 位置に1個ずつ。凸を交差点中心向き
  - 高さ: 道上面 + 5mm (Zファイト回避)
- 描画: InstancedGroup で全ジョイントを1ドローコールにまとめる
- jointVisible=editor のときはゲーム実行時に非表示

## 3. 管理UI (レールエディタに「接続」タブ追加)

- 接続一覧: ノードごとに [種類(溶接/T/十字) | 参加レール名 | 距離位置]
- 行選択 → GameView で該当ノードとジョイントをハイライト
- 「切断」ボタン: ノードを分離し、道・パッチ・ジョイントを再生成。
  分離後の端点は 0.3m だけ離す (即再スナップの無限ループ防止)
- すべて既存の履歴 (Ctrl+Z / Ctrl+Y) に統合する

## 4. 再生成の範囲

接続/切断/ノード移動時: 関係するレールの道メッシュ + 該当ジャンクションパッチ +
ジョイント配置のみ再生成 (全レール再生成はしない)

## 5. 受け入れ条件

- [ ] 端点を他レールの端点/途中へ近づけると緑プレビューが出て、離すと繋がる
- [ ] 接続点にジョイントが表示され、交差点では入口ごとに凸が中心を向く
- [ ] autoSnap OFF で従来の手動ボタン運用に戻る
- [ ] 接続一覧から選択ハイライトと切断ができ、Ctrl+Zで元に戻る
- [ ] ジョイント追加によるドローコール増加は合計 +1 (インスタンス描画)
- [ ] シーン保存/ロード後もジョイントがノードから正しく再導出される

## 6. テスト手順

1. 端点→端点スナップ (ゆるい角度/鋭角の両方)
2. 端点→レール途中スナップでT字化、パッチとジョイント3個を確認
3. snapDistance を 0.3 / 3.0 に変えて挙動確認
4. 切断→再スナップ→Ctrl-Z×2 で完全に元へ戻ること
5. 保存→再起動→ロードでジョイント再現
6. パフォーマンスモニターでドローコール +1 を確認

## 8. レールごとの道生成 ON/OFF

レールを引くと必ず道が付く現状を、レール単位で選べるようにする。

- レールエディタの路線リスト各行に「道」トグルを追加: **自動 / なし** (既定: 自動)
- 設定はシーンデータに保存する (既存シーンは全レール「自動」として読む)
- 「なし」のレール:
  - 道メッシュ・坂UV・穴処理を生成しない。ジョイントも表示しない
  - ジャンクションでは方向として数えない。その結果、接続ノードで
    道ありの方向が **2本以上残る**→通常のパッチ / **1本だけ**→road_endでキャップ /
    **0本**→何も生成しない
- (任意・Should) 同じ行にレール単位の heightOffset と幅倍率も出す
  (カメラ用レール・敵専用レール・演出用の見えないレールに使う想定)

受け入れ条件:
- [ ] トグル切替で該当レールの道・ジョイントだけが即時に出入りする
- [ ] 「なし」レールが混ざる接続ノードで上記3分岐が正しく機能する
- [ ] 保存→ロードで設定が復元される

## 9. 編集中のパフォーマンス修正 (ドラッグが重い問題)

### 9-1. 原因の切り分け (実装前に必ず計測)
ノードをドラッグしながらパフォーマンスモニターを見る:
- Update が跳ねる → 再生成の呼びすぎ/全レール一括再生成 (→9-3, 9-4)
- Draw やフレーム全体が跳ねる/カクつく → **GPUバッファの毎フレーム作り直し** (→9-2)
  ※道の生成自体は実測1ms未満なので、重さの主犯はほぼこちら

### 9-2. 固定容量の動的バッファ (最重要)
- レールごとに UPLOAD ヒープの VB/IB を起動時に1回だけ確保し、Mapしたまま保持
  - 既定容量: 頂点 4096 / インデックス 24576 (調整項目化)
- 再生成 = **確保済みバッファへ memcpy + 描画数の更新のみ**
  - CreateCommittedResource / GPU完了待ち(Flush, WaitForGPU) を編集中に呼ばない
  - GPUが前フレームを読んでいる間の書込みが不安なら2面リング(フレーム毎交互)にする
- 容量を超えたときだけ2倍サイズで作り直す (稀)

### 9-3. ダーティフラグによる差分再生成
- ノード変更のあったレールにだけ dirty を立て、そのレール +
  そのレールが参加するジャンクションパッチ + ジョイントのみ再生成
- 他レールには一切触らない

### 9-4. ドラッグ中は軽量プレビュー + スロットリング
- ドラッグ中の再生成は最大 10回/秒 に間引く
- ドラッグ中は簡易生成に切替 (調整項目 editPreview: full / simple / hidden, 既定 simple)
  - simple: ds固定1.0m・溶接/坂UV/パッチ/ジョイント/穴を省略した素のリボン
  - hidden: 道を消してレール線のみ
- マウスアップで通常の本生成を1回実行

受け入れ条件:
- [ ] ノードドラッグ中も FPS 55以上 / Update増分 2ms未満
- [ ] ドラッグ中にVRAM使用量が増え続けない (バッファ作り直しゼロの確認)
- [ ] マウスアップ直後の1フレームで最終形になる
- [ ] 20m級レール(頂点容量ぎりぎり)でも破綻しない
