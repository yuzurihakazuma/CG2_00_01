# かくかく対策ガイド (滑らかな道にする4つの方法)

比較画像: smooth_before.png (均一0.5m) / smooth_after.png (適応3°)
検証結果: 同じレールで リング数 66(均一0.5m) / 115(適応3°) / 218(均一0.15m)
→ 適応サンプリングは総当たりの約半分のコストで同等の滑らかさ。

かくかくの原因は3種類あり、効く対策が違う:
| 原因 | 症状 | 対策 |
|---|---|---|
| リング間隔が粗い | カーブの輪郭が多角形 | ①曲率適応サンプリング |
| 陰影がフラット | 面ごとに明るさが段々 | ②スムーズ法線 |
| レール自体が折れ線 | ノードの所だけ角が残る | ③角の丸め(フィレット) |

---

## ① 曲率適応サンプリング (最優先・効果大)

「等間隔」をやめて「曲がった角度の合計が閾値を超えたらリングを置く」に変える。
直線は1mおき、カーブは自動的に密になる。

```
// 元カーブを細かく歩く (0.05m刻みなど)
accAngle += acos(clamp(dot(prevDir, dir), -1, 1));  // 方向変化を積算
accLen   += stepLen;
if ((accAngle > 3°(0.052rad) && accLen > 0.06f) || accLen > 1.0f) {
    リングを置く;
    accAngle = accLen = 0;
}
```

- 閾値3°で1リングあたりの折れが最大3° → ほぼ目視で分からない
- accLen > 0.06f は鋭角に無限にリングが集まるのを防ぐ下限
- 「元カーブを細かく歩く」は GetPositionAtDistance を 0.05m 刻みで呼ぶだけ

## ② スムーズ法線 (シェーディングを丸くする)

ポリゴンが粗くても、法線が滑らかなら陰影は丸く見える(逆も然り)。
- 法線は必ず「そのリングのフレーム」から解析的に出す:
  `n = right * nr + up * nu` (断面表の値)。**面法線から計算しない**
- 進行方向には頂点を共有(または同位置・同法線で複製)して、
  リング間で法線が連続するようにする
- 横方向のハードエッジ(ベベルの折り目・壁の角)は今のまま別頂点でOK。
  クラフト紙らしさはこの折り目が担う

これが入っていれば①のリング数をさらに減らしても綺麗に見える。

## ③ レール折れ線の角を丸める (ノードで角が残る場合)

①②をやってもノード位置だけカクッと残るなら、レールが直線チェーンの箇所。
サンプリングを増やしても「角そのもの」は消えないので、生成前にパスを丸める:

- 方法A: ノード列を Catmull-Rom で補間した曲線から道を生成
  (レールエディタの「なめらか化」と同じ発想を生成側でやる)
- 方法B: 角フィレット — ノードの前後 r(=0.5m程度) を円弧に置き換える
- 注意: プレイヤー移動が折れ線のままだと道と移動が最大 r ずれる。
  移動側にも同じ補間を使うと操作感も滑らかになって一石二鳥
  (ずれを出したくない箇所は r を小さく)

## ④ GPUテッセレーション (参考・非推奨)

D3D12のハル/ドメインシェーダで距離・曲率に応じてGPU分割する方法もあるが、
道の頂点数は①で数百〜千程度に収まるため、実装コストに見合わない。
「画面に道が数万メートル分ある」規模になったら検討で十分。
