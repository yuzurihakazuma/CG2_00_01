## 修正1: カーブや坂で道がねじれる・反転する

### 原因
毎サンプルで `right = cross(worldUp, tangent)` を計算していると、
接線が上下(worldUp)に近づいた瞬間に right の向きが不安定になり、
1サンプルで道が90°〜180°回転する。急坂・縦カーブで必ず起きる。

### 修正: 前のフレームを引き継ぐ (平行移動フレーム / RMF)
最初の1回だけ cross で作り、以降は「前の right を新しい接線に直交化」して使う。

```
// 初期化 (i = 0)
right = normalize(cross(worldUp, tangent[0]));

// 各サンプル i
right = right - dot(right, tangent[i]) * tangent[i];  // 新接線に直交射影
right = normalize(right);
up    = cross(tangent[i], right);
```

これだけで縦カーブ・急坂でも連続的に回り、反転しない。

### 追加: ロール回復 (推奨)
垂直区間を抜けた後に道が傾いたまま残ることがあるので、
接線が水平寄り (|tangent.y| < 0.7) のときは理想の right へ少しずつ戻す:

```
if (abs(tangent.y) < 0.7f) {
    ideal = normalize(cross(worldUp, tangent));
    if (dot(ideal, right) < 0) ideal = -ideal;   // 反転して戻さない
    right = normalize(lerp(right, ideal, 0.15f)); // 毎サンプル15%ずつ回復
}
```

## 修正2: 急カーブ(半径 < 道の半幅1m)で内側が潰れる

### 原因
カーブ内側の頂点は「進行方向と逆向き」に動くため、リングが折り返して
面が裏返り、Z-fightや潰れが起きる。

### 修正: 内側折返しの溶接 (3行で済む)
新リングの各頂点について、前リングの同じ頂点からの移動が接線と逆向きなら
前リングの位置をそのまま使う:

```
// 頂点 j を配置した後
if (dot(newPos[j] - prevRing[j], tangent[i]) < 0.0f) {
    newPos[j] = prevRing[j];   // 折返し → 前の位置に溶接
}
```

内側は扇状に畳まれ、外側は普通に回る。見た目は紙を折ったようになり自然。
※ ds(サンプル間隔)を曲率に応じて細かくする(0.3→0.15m)とさらに滑らか。

## 修正3: 坂(山)の雰囲気が分かりづらい

### 対策A: 坂用テクスチャ帯への切替 (アトラスv4に追加済み)
急な区間の上面だけ「滑り止めの横桟」入りの帯に切り替える。
0.5mごとにクラフト風の桟が入るので、傾斜が一目で分かる。中央破線は継続。

```
bool steep = abs(tangent.y) > 0.40f;   // 約24°以上を坂とみなす
// 上面2頂点(表の#4,#5)の v だけ切替:
通常: v = 0.7500 (左) / 1.0000 (右)
坂  : v = 0.0234 (左) / 0.2031 (右)
u は今まで通り 距離/2.0 (坂帯も全幅なのでREPEATが効く)
```

きれいに切り替えるコツ: 平坦↔坂の境目では **同じ位置にリングを2重に置き**、
1つ目は旧帯のv・2つ目は新帯のvにする(帯が引き伸ばされて混ざるのを防ぐ)。
1リングだけの点滅を防ぐには判定にヒステリシス(入り0.45/抜け0.35)を付ける。

### 対策B: 陰影を効かせる (確認)
リングの法線を「right/up基準」で出しているか確認
(`n = right*nr + up*nu`、nr/nuは断面表の値)。ワールド固定の法線だと
坂も平地も同じ明るさになり、立体感が消える。

### 対策C (任意): 高さで色を変える
生成時に頂点カラー、またはピクセルシェーダで
`color *= lerp(0.92, 1.08, saturate(worldY / maxHeight))` のように
高いほど明るくすると、遠目でも高低が分かる。1行で効果大。
